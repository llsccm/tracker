# 问卦（SpellID=780）：主动交牌与回堆

## 当前支持范围与取舍

原问卦单实体追踪器已替换为低复杂度的候选来源筛选器。
所有消息仍经过通用协议归一化和实体移动；仅第三方可可靠配对的暗交牌/回堆消息补充候选来源。

- 相关角色能看到交牌及回堆的真实 CardID，通用已知牌移动已经能够关联同一身份。
- 第三方看不到这些消息中的真实 CardID，不能借用交互视角的身份补全第三方消息。
- 原实现只保存一个 `trackedCard` 并在回堆时指定 `sourceCards`，不能表达“多张候选中恰有一张
  被交出、随后原牌回堆”的跨消息数量关系，因此不再保留这层单实体关联。
- 新实现只防止接收者原有明牌被错误扩散，保存的是已知身份 ID 集合及配对信息，不指定物理来源实体，
  不补写 `cardIDs` 或 `pileIdentityCardIDs`。完整批次数量关系与精确收敛仍未实现。

## 已确认的协议语义

- `MoveType=27` 表示**主动交给**，通用常量为 `MOVE_TYPE.GIVE`，不是反间或问卦专用类型。
- 主动交给描述移动原因，不保证 CardID 公开，也不意味着服务器随机选择了被交出的牌。
- 已确认问卦的交牌与对应回堆两条消息相邻；实现按这个协议约定配对，不监听其它技能移动。
- `FromZone=5` / `ToZone=5` 表示玩家手牌区；跨座位主动交牌不是同区展示。
- `FromPosition=65282` 描述来源位置，不能据此把回堆目标解释为随机。
- `ToZone=1, ToPosition=0` 是明确放到牌底；回顶使用通用的 `65280` 语义。
  顶、底和随机的统一解释见 [公共区目标位置](move-position.md)。

## 交互视角原始样例

以下两条消息来自相关角色的可见视角。角色 1 将 `134` 交给角色 4，随后角色 4 将同一张牌
放到牌堆底。两条消息都公开了 `CardIDs: [134]`，不需要技能处理器再次补出身份。

### 1. 主动交给角色 4

```yaml
CardCount: 1
CardIDs: [134]
FromID: 1
FromPosition: 65282
FromZone: 5
FromZoneParam: 0
MoveType: 27
SpellID: 780
ToID: 4
ToPosition: 65280
ToZone: 5
ToZoneParam: 0
```

### 2. 角色 4 放到牌堆底

```yaml
CardCount: 1
CardIDs: [134]
FromID: 4
FromPosition: 65282
FromZone: 5
FromZoneParam: 0
MoveType: 15
SpellID: 780
ToID: 255
ToPosition: 0
ToZone: 1
ToZoneParam: 0
```

这条回底消息不会触发随机入堆匿名化。第三方视角不接收上述真实 ID；没有真实 ID 的消息按
其实际数组和 `CardCount` 处理。本页未收录第三方原始报文，也不把修改上述样例得到的数组
形式当成已确认的第三方协议。

## 候选来源筛选（已实现）

设 A 有已知手牌 X、Y 和一张暗牌，B 原有已知手牌 Z。第三方只知道 A 交了一张牌给 B，
随后 B 将刚收到的那张放到牌底，但不知道具体身份。

1. 无正 ID 的单张主动交牌（`MoveType=27, 5 -> 5`）发生前，记录 A 的已知手牌身份集合，
   包含已候选于 A 的明牌；状态仅保存来源身份集合和双方座位。
2. 相邻的无正 ID 单张回顶/回底（`MoveType=15, 5 -> 1`）若来源仍为 B，
   通过 `MoveOptions.publicCandidateSource` 传递 A 的候选来源。
3. 实体移动和手牌数量变化仍按 B 回堆执行。候选传播仅考虑快照中当前仍可能位于 B 手牌的
   已知牌，给 X、Y 添加顶/底候选，不因本次回堆给 B 原有的 Z 增加公共区候选。
4. A 全暗时显式传递空集合；空集合表示不扩散已知牌，不能回退为 B 的全部明牌。
5. 对涉及来源集合的旧约束组，保守失效 A/B 的手牌数量条件及兼容读面。旧的“B 收到一张”
   不能在回堆后继续强制成立；旧的 A 名额也不能因某个匿名代表被移走而错误排除明牌回堆的可能。
   不新建精确的公共区批次名额约束。

### 配对与失效边界

- 筛选器仅按 `SpellID=780` 注册，不作为 `*` 全局观察器，不处理其它技能的移动。
- 每条问卦移动先消费旧记录；新的暗交牌重新记录来源，回堆则校验数量、类型、座位及顶/底位置。
  不匹配或协议已公开身份时不应用旧名单，继续通用移动。
- 信任已确认的相邻协议约定，不为中间插入其它移动、跨回合或独立揭示额外保存和监测状态。
- 配对完成即删除记录；新 Room、重新初始化或结束对局沿用统一 GameState 生命周期清理。
- 无记录或无法可靠配对时，不拦截协议移动，不猜测身份，保留原有通用处理。

### 通用接口边界

`publicCandidateSource = { fromSeat, cards }` 中的 `fromSeat` 是最初交牌者 A，`cards` 是候选
来源集合；实际 `fromSeatID` 仍是回堆者 B。该选项只筛选公共区候选并失效旧手牌约束，
不能代替 `sourceCards`、修改物理来源或作为身份账本的已知 ID 输入。选项省略时，通用暗回堆
仍按回堆者手牌集合传播候选。

## 尚未实现：完整批次数量关系与精确收敛

- X、Y 仍可能保留“A 手牌 / B 手牌 / 牌顶或牌底”的较宽候选，不保证仅凭问卦关联立即缩小为
  “A 手牌 / 对应公共槽位”。其它已有事实能够收敛时，继续由通用约束处理。
- 未建立“X、Y 与暗牌共同竞争同一个回堆名额”的完整批次约束，也不保证识别实际返回的牌面。
- 对受影响的旧 A/B 手牌约束采用保守失效，不尝试逐项迁移到公共区；这会损失部分推断精度。
- 未支持偏离相邻协议约定的长链配对，也不监测跨技能事件。可识别的失配回退通用逻辑，仍可能把回堆者原有明牌纳入
  公共候选，因此“B 原有明牌不被扩散”的保证仅适用于成功配对的筛选路径。
- 不维护完整交牌批次的后续取牌、揭示和中断历史；以后若需要更精确推断，应优先设计可复用的
  “收到后原样转移”批次机制，而不是恢复单个匿名实体追踪或补造真实 CardID。
